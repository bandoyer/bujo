# Slice 1.5.5 - core notation and hierarchy fidelity

Status: **LANDED 2026-08-29 - terminal candidate `70b9c742`, integrated on
`main` at `867e3b28`. Deployment is not authorized.**

This is the last bounded method-spine slice in phase 1. It adds Ryder
Carroll's remaining core signifier, `!` for inspiration, and makes the
existing Entry hierarchy honest: a master task cannot be completed while a
subtask is still live. It also exposes one decision the prior plans missed:
the Rails app can render nested entries but currently has no normal gesture
for creating one.

The authority order is `docs/METHOD.md` -> `PLAN.md` -> `ARCHITECTURE.md` ->
this contract. The source check used *The Bullet Journal Method*, Part II,
especially printed pages 68-69 (Subtasks and Master Tasks) and 80-82
(Signifiers and Custom Bullets; PDF pages 62 and 74-76). The source says that
signifiers add context in front of a bullet, describes `!` as Inspiration and
most commonly paired with a Note, and allows a master task to complete only
after its subtasks have been completed or marked irrelevant. "Most commonly"
is guidance, not a kind restriction.

## Current-source audit

The landed application already has most of the required spine:

- `Bujo::RapidLog::Parsed` carries one `priority` boolean; the grammar and
  canonical renderer recognize only `*`.
- `entries.priority` is persisted, corrected in place, copied through every
  append-only movement/Undo successor, rendered in one shared signifier
  column, and changed independently by Morning Reflection.
- `entries.parent_id` supports same-user nesting at any depth. Children share
  their parent's immutable residency, render recursively through kept child
  edges, and never move automatically with a parent.
- `Entry#complete!` currently checks only that the named row is an open task.
  A parent with an open task child therefore completes today.
- ordinary source pages and Evening Reflection reach that same model command;
  Monthly Migration intentionally offers no Complete command.
- the Rails UI has no child-capture route or control. Existing nested rows can
  arrive only from fixtures, direct domain use, or a later sync client. Calling
  the web hierarchy "usable" without settling that gap would be misleading.

## Acceptance contract

- `!` is an Inspiration **signifier**, not an Entry kind, task state, tag, or
  custom bullet.
- Priority and inspiration are independent context and may coexist on one
  Entry. Canonical order is `*` then `!`; neither action silently erases the
  other.
- A standalone leading `!`, or `!` before a recognized bullet glyph, parses
  through the shared rapid-log grammar on every existing capture and Edit
  surface. There is no second parser and no new signifier toolbar.
- Every capture, correction, append-only movement, compensating Undo, render,
  and future sync snapshot preserves the inspiration value exactly.
- An open task with any live task descendant is a master task. Complete is
  admitted only when every such subtask's current append-only chain ends in
  `done` or `struck`.
- The completion check is atomic at the model boundary. Hiding a control is
  never the security or integrity boundary; a crafted or stale request is
  refused without changing any row.
- Completing, striking, reopening, moving, correcting, or writing beneath one
  row never cascades to its parent, descendants, predecessor, or successor.
- The approved web hierarchy gesture writes one Entry beneath an eligible open
  task, derives residency and ownership from that persisted parent, and uses
  the shared Task/Event/Note rapid-log anatomy. Whitespace or text parsing
  never creates hierarchy by itself.
- UUIDv7, immutable residency, append-only movement, same-user validation,
  exact task/non-task state, soft deletion without cascades, the unique
  successor chain, and dormant `hlc`/`server_seq` behavior all remain binding.

## Approved digital translations

The operator approved both product choices on 2026-08-28. They are binding for
this slice.

### 1. Independent signifiers may coexist (approved)

Keep the landed `priority` boolean and add an independent `inspiration`
boolean. This is the smallest lossless extension of the existing sync-shaped
row. It lets Morning Reflection mark a task important without deleting an
inspiration marker, and it lets Edit change either marker through the same
canonical line. The shared signifier column renders `*`, `!`, or `*!`.

The rejected minimal alternative is a mutually exclusive enum. It would make
Mark priority either erase `!` automatically or refuse until the reader edits
the inspiration away. Neither behavior comes from the method.

### 2. Add the missing write-beneath gesture now (approved)

An eligible open task offers `Add below…`. The revealed step reuses the
current three kind controls and rapid-log field under the label `Add below`,
then persists one child on submit. A Task child is a subtask for completion
gating; an Event or Note child is supporting context under the existing page
grammar.

This closes the current usability gap without indentation parsing, drag/drop,
outlining controls, or automatic hierarchy. The narrower alternative is to
ship only completion gating for imported/future-sync trees and leave Rails
unable to create a master task. The operator rejected that alternative; the
mock records the approved step.

## Rapid-log grammar

`Bujo::RapidLog::Parsed` becomes exactly:

```ruby
Bujo::RapidLog::Parsed = Data.define(
  :kind,
  :state,
  :priority,
  :inspiration,
  :text,
  :date,
  :time,
  :tags,
  :raw
)
```

The only grammar expansion is the signifier prefix:

```text
line       := [signifiers ws] [glyph ws] text [end-zone]
signifiers := signifier (ws signifier)*
signifier  := "*" | "!"
```

All slice 1.1 normalization, glyph, date/time/tag end-zone, default-kind,
never-raise, and round-trip rules remain unchanged.

Exact prefix rules:

- A signifier is recognized only as a complete leading token followed by
  whitespace or end of input. `! idea` is inspired; `!important` and an
  exclamation point later in the line are ordinary text.
- Signifiers may appear alone before the text or before one recognized glyph:
  `! – Keep this insight`, `! Keep this insight`, and `* ! • Ship the fix`.
- `*` and `!` may appear in either input order. Repeated leading signifier
  tokens collapse to their two booleans rather than creating duplicate data.
- Concatenated `!*`/`*!` is ordinary text, preserving the existing
  whitespace-delimited grammar instead of adding a second spelling.
- Canonical render order is `["*", "!", glyph, text, tags, date, time]` with
  absent values removed and one space between tokens.
- A line containing only signifiers and/or a glyph still parses to nil because
  its cleaned text is empty.
- `!` may accompany Task, Event, or Note. The source's "most commonly paired
  with a Note" does not become a false structural validation.

Ruled additions, with `today: 2026-08-28`:

| Input | Kind/state | Priority | Inspiration | Text |
|---|---|---:|---:|---|
| `! – Keep the recovery path simple` | note / NULL | false | true | `Keep the recovery path simple` |
| `! A calmer morning` with Note selected | note / NULL | false | true | `A calmer morning` |

| `!` | nil | - | - | - |

## What counts as a subtask

For completion gating, a subtask is any **task Entry** reachable below the
master through recursively kept child edges, at any depth.

- Traversal walks through kept Tasks, Events, and Notes so a deeper task still
  counts even when contextual non-task rows sit between it and the master.
- Event and Note descendants never block completion themselves; their state
  remains exactly NULL.
- A soft-deleted child cuts off its branch, matching every landed page and
  lens renderer. A kept grandchild hidden beneath that tombstone is not made
  into an invisible blocker.
- A foreign-user or structurally inconsistent relation is never ignored as if
  it were satisfied. Supported APIs already prevent it; if encountered during
  the command check, completion refuses without exposing the other row.
- Children added after a valid completion do not rewrite history or
  automatically reopen the master. Reopen and later child work remain
  deliberate commands. This slice gates the Complete command at the moment it
  is made; it does not install a cascading state invariant.

### Append-only movement does not abandon a subtask

A moved task child stays visibly nested as its `>`/`<` predecessor while the
successor is a new root on its destination page. The completion check follows
that same-user append-only task chain to its current kept endpoint:

- live endpoint `done` or `struck` -> that subtask is satisfied;
- live endpoint `open` -> it blocks;
- another migrated endpoint -> continue following the chain;
- missing, tombstoned, cross-user, non-task, or otherwise malformed endpoint
  -> block and refuse rather than silently declaring the work complete.

The check is observational. It does not move the successor back, reparent it,
copy a subtree, alter a predecessor, or mark any child automatically.

### Atomic `complete!`

`Entry#complete!` remains the one domain boundary for ordinary pages and
Evening Reflection. In one transaction it reloads/locks the named current
task, verifies the existing `open`/kept/no-successor lifecycle conditions,
evaluates its current kept descendant chains, and writes only `state: "done"`
when every task chain is satisfied.

Any blocker raises `Entry::LifecycleError`. Refusal leaves the master,
descendants, successor chains, timestamps, and sync placeholders unchanged.
The database is not claimed to prove this graph rule for arbitrary SQL.

Strike, Reopen, Migrate, Schedule, Move to Collection, Edit, and Monthly
Migration retain their current rules. In particular, the app does not forbid
striking or moving a master merely because it has open children, and children
still do not follow a moved parent.

## Write-beneath gesture

### Eligibility

`Add below…` is rendered only for a kept, current-user, open Task with no
successor whose complete kept ancestor path is visible and whose resident
source page admits direct writing now:

| Parent residency | Add below |
|---|---|
| Daily today/past | allow |
| Daily future day | absent; crafted request refuses |
| Monthly Calendar current/past | allow |
| Monthly Tasks current/past | allow |
| either Monthly page in a future month | absent; crafted request refuses |
| kept Custom Collection | allow |
| Future Log | absent; crafted request refuses |
| Morning or Evening Reflection lens | absent; use the source page |
| Monthly Migration lens | absent; context remains read-only |

A done or struck task must first be reopened. A migrated predecessor, any row
with a successor, an Event, a Note, a tombstone, a hidden descendant, a
foreign id, or a resident of an unavailable Collection cannot receive a
child through this command.

### Capture behavior

- The action reveals one inline step under the selected task, matching the
  current Edit/capture anatomy: shared Task/Event/Note circles, label
  `Add below`, rapid-log field, `Log`, and `Cancel`.
- The parent is the route subject. The browser may submit line and selected
  kind only; `user_id`, parent id, placement, Collection, history, state,
  deletion, timestamp, `hlc`, and `server_seq` claims refuse the whole request.
- The server derives user, `parent_id`, `page_kind`, `page_on`, and
  `collection_id` from the persisted parent. It never trusts return or
  placement parameters as authority.
- Parser `today` follows the landed resident-root rule: Daily root day,
  Calendar root occurrence, and request-snapshotted today for Monthly Tasks
  and Collection. Admission uses the request's one snapshotted `@today`.
- Task/Event/Note selection is genuine. A glyph in the line may override the
  selected kind exactly as ordinary capture does. Any child kind is valid
  supporting context under the landed structural grammar; only Task children
  participate in completion gating.
- Blank parse is a quiet no-op. Invalid text, stale eligibility, or a crafted
  claim refuses atomically and retains the submitted line/kind where possible.
- Success creates one fresh UUIDv7 child in capture order. It creates no root,
  successor, Collection, Index row, or copied subtree, and changes no existing
  Entry.
- Leading spaces or typed indentation remain ordinary whitespace
  normalization. Hierarchy is chosen only by the explicit parent-row gesture.

Nested children may themselves use `Add below…` while eligible, so arbitrary
depth remains supported without drag/drop, indent/outdent, or reparenting.

## Complete rendered/crafted command matrix

This table is additive to the landed command policy. `Edit`, Strike, Reopen,
Migrate, Schedule, and Move to Collection otherwise keep their existing
residency/state rules.

| Current row/context | Complete rendered | Add below rendered | Crafted Complete | Crafted Add below |
|---|---|---|---|---|
| open leaf Task on actionable Daily/Monthly source | yes | yes when page is writable | succeeds | succeeds when eligible |
| open Task whose task descendants all end done/struck | yes | yes when page is writable | succeeds | succeeds when eligible |
| open Task with any blocking descendant chain | **no**; show reason in its open strip | yes when page is writable | refuses unchanged | succeeds when eligible |
| done/struck Task | no; Reopen as today | no | refuses unchanged | refuses unchanged |
| migrated Task or any row with successor | no controls as today | no | refuses unchanged | refuses unchanged |
| Event/Note | never | never | refuses unchanged | refuses unchanged |
| actionable Collection Task | same lifecycle rows above | yes | same gate | same eligibility gate |
| Future resident | no commands | no | refuses unchanged | refuses unchanged |
| Evening open Daily Task | yes only when gate passes | never in lens | same gate and safe Evening return | refuses |
| Morning/Monthly Migration context | no Complete in lens | no | existing source/ritual policy | refuses |
| missing, foreign, tombstoned Entry | none | none | nondisclosing 404 | nondisclosing 404 |
| Collection resident whose Collection is missing/foreign/deleted | none | none | uniform Collection 404 | uniform Collection 404 |

For a blocked master, the ordinary and Evening action strips omit Complete and
show the exact quiet helper `Complete or strike every subtask first.` It is
not a disabled button, alert, badge, input-like notice, or automatic link.
When the last blocker resolves, the next render shows the ordinary Complete
button with no celebratory state.

A stale Complete POST - for example, a child reopened in another tab after
the button rendered - follows the established refusal alert `That entry can't
do that.` and changes nothing. The model gate, not the rendered helper, is the
authority.

## Return, refusal, and focus

- Ordinary Complete success keeps its existing source-page return. Dated
  pages return to the viewed page; Collection residents return to their
  canonical persisted Collection; Evening returns to Evening Reflection.
- Blocked/stale Complete refusal returns to the same safe destination with the
  established alert and the master still open.
- Add-below success returns to the parent's canonical persisted source page,
  expands/focuses the new child row, and preserves page order. It never accepts
  an arbitrary URL.
- Add-below validation refusal returns to that same source, reopens the parent
  step, retains submitted line/kind where possible, and focuses the field.
  Cancel is browser-local and writes nothing.
- Missing, foreign, and tombstoned ids remain indistinguishable. No response
  discloses Entry text, owner, residency, parent, blockers, or Collection
  existence across tenants.
- Every refusal reload-proves the named row, every reachable descendant, and
  all movement rows unchanged; no unrelated Entry is written.

## State, sync, and security boundaries

- Every new Entry id is UUIDv7. Caller-supplied ids for future sync retain the
  existing model contract; the web form never supplies one.
- Child ownership and immutable residency derive from the current-user kept
  parent. Parent, child, Collection, predecessor, and successor must remain
  same-user through supported APIs.
- `page_kind`, `page_on`, and `collection_id` never mutate after creation.
  Add-below creates in place; moving still appends a root successor.
- Task state remains exactly `open | done | struck | migrated`; Event/Note
  state remains exact NULL. Inspiration creates no state value.
- `soft_delete!` remains non-cascading. Tombstones keep inspiration and links;
  kept render/traversal boundaries remain explicit, with no `default_scope`.
- Completion and child capture touch neither `hlc` nor `server_seq`; both stay
  NULL unless already populated and unchanged. Inspiration is documented as a
  future synced field but does not activate sync.
- No new query accepts user, parent, Collection, page, blocker, or return
  authority from the request. All mutation lookups start from
  `Current.user.entries.kept` / `Current.user.collections.kept`.
