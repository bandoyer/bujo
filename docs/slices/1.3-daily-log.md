# Slice 1.3 — the Daily Log

You are building bujo's first real screen: the Daily Log — rapid-log
bar, entry list with lifecycle actions, day navigation — plus the
theme system every later screen inherits. Hotwire only: server-rendered
ERB, Turbo, Stimulus via importmap. No new gems, no build step, no CSS
framework — the styles are hand-rolled from the token tables below.

Read `PLAN.md`, the `bujo-conventions` and `testing` skills, and the
visual spec: the mobile artboards in
[bujo-mockups](https://github.com/bandoyer/bujo-mockups) —
`Today.dc.html` is the light theme, `AltDark.dc.html` the dark
direction. **This spec pre-decides the judgment calls; report gaps
instead of inventing rulings.**

## Routes and controllers

```ruby
root "daily_logs#show"
get "daily(/:date)", to: "daily_logs#show", as: :daily_log   # date: ISO, defaults to today
resources :entries, only: :create do
  member do
    post :complete
    post :reopen
    post :strike
    post :migrate    # to the first day of the next month
    post :schedule   # param date: ISO — sets occurs_on
  end
end
resource :theme, only: :update  # cookie-backed, see Themes
```

- Controllers are the one layer that reads the clock. Set
  `config.time_zone = "America/New_York"` in application.rb; day
  boundaries follow it. (Per-user timezones are a non-goal.)
- `DailyLogsController#show`: parse `params[:date]` as ISO (invalid or
  missing → today, no error page); load
  `Current.user.entries.daily_log(date)`.
- `EntriesController#create`: `Entry.capture!(params[:line],
  user: Current.user, today: Time.zone.today, default_kind:
  params[:default_kind])` — blank parse (nil) is a quiet no-op.
  Responds with a Turbo Stream that appends the entry (rendered via
  the shared partial, nested children included) and resets the form.
- Action endpoints call the model's bang methods, then redirect back
  to the day being viewed (Turbo Streams for the single row are
  allowed but not required). `rescue_from Entry::LifecycleError` at
  the controller: flash alert "That entry can't do that.", redirect
  back — never a 500.
- `migrate` targets the first day of the month after the *viewed*
  day; `schedule` requires a `date` param (the UI supplies a date
  input). Both act only on open tasks — the model enforces it.
- Everything requires authentication (the generator's concern already
  defaults to it); root moves from the sign-in placeholder to the
  Daily Log.

## The screen (match `Today.dc.html`)

Mobile-first: a single column, `max-width: 28rem`, centered on wider
screens. Top to bottom:

1. **Header** — small mono eyebrow `SUN · AUG 24` style (the viewed
   day), serif "Daily Log" title, right-aligned open-task count
   (`N open`, count of open tasks in the viewed day). Chevron
   links navigate to the previous/next day; when viewing a day other
   than today, a small "today" link jumps back.
2. **Entry list** — one row per root entry from `daily_log`, children
   nested beneath their parent with an indent. Row anatomy per the
   mock: signifier column (`*` when priority), mono glyph column
   (`entry.glyph`), text, right-aligned mono meta (time for events,
   `→ …` for migrated, tags as `+tag`). Struck entries render with
   line-through text — the bullet stays. Done and migrated rows are
   muted. Each task row exposes its actions (complete/reopen/strike/
   migrate/schedule) as real buttons in a compact row-level menu or
   inline cluster — coder's layout call, but hit targets ≥ 44px and
   plain `<form>`/`button_to` semantics, no JS-only click handlers.
3. **Rapid-log bar** (bottom, thumb reach) — the kind toggle (three
   44px circles: `•` `○` `–`, a Stimulus controller sets the hidden
   `default_kind` field) and the rounded text input, placeholder
   "Rapid log…". Submitting appends and clears; focus stays in the
   input.
4. **Tab bar** — four items per the mock (Today, Month, Future,
   Index); only Today is live. The other three render as disabled
   placeholders (no dead links) until their slices exist.

No fake device chrome. Empty day: an unobtrusive centered line
("Nothing logged yet.") between header and bar — nothing else.

## Themes (the foundation every screen inherits)

Token-based CSS in `app/assets/stylesheets/`: define the palette as
custom properties on `:root` (light is the base), redefine only tokens
under `@media (prefers-color-scheme: dark)` guarded as
`:root:not([data-theme="light"])`, and again under
`[data-theme="dark"]` so the explicit choice wins both ways. Never
give a color its only definition inside a media/`[data-theme]` block.

Light — "paper" (from `Today.dc.html`):

| Token | Value | Role |
|---|---|---|
| `--bg` | `#f6f1e6` | page (with the dot-grid: `radial-gradient(rgba(32,29,24,.09) 1px, transparent 1.1px)` / `22px 22px`) |
| `--surface` | `#fdfaf2` | input, cards |
| `--ink` | `#201d18` | text |
| `--muted` | `#8d8574` | meta, secondary |
| `--faint` | `#a39a89` | done/migrated text, inactive tabs |
| `--line` | `#e0d8c4` | rules, borders |
| `--accent` | `#a8722a` | events, priority, today |
| `--warn` | `#a0524a` | strike action |

Dark — "terminal-kin" (Tokyo Night, from the TUI mocks): `--bg`
`#16161e`, `--surface` `#1a1b26`, `--ink` `#c0caf5`, `--muted`
`#565f89`, `--faint` `#565f89`, `--line` `#2f3549`, `--accent`
`#7aa2f7`, `--warn` `#f7768e`; events may use `#7dcfff`, done `x`
stays muted, no dot-grid (flat dark ground).

Type: Newsreader (serif display), Public Sans (body), JetBrains Mono
(glyphs, dates, meta) via Google Fonts `<link>` tags with real
fallback stacks — vendoring the fonts locally is deliberately
deferred to slice 1.7 (PWA/offline), leave a `# TODO(1.7)` comment at
the link site.

**The toggle**: three-state (system → light → dark), a small control
tucked in the header. State lives in a `theme` cookie (`system` =
absent). The layout stamps `<html data-theme="...">` server-side from
the cookie — no flash of wrong theme — and `ThemesController#update`
sets the cookie (permanent, `same_site: :lax`) and redirects back. A
tiny Stimulus controller submits the cycle; no localStorage.

## Ruled flows (the system-test contract)

These become `test/system/daily_log_test.rb` (grow
`sessions_test.rb`'s helper into a shared sign-in). All through the
real browser, fixture user `one`:

1. Sign in → lands on today's Daily Log with the weekday eyebrow and
   the open count. Ruling for the whole lane: system tests never
   freeze the clock and never rely on fixture entries with fixed
   dates — they create entries through the UI and compute expected
   dates from `Time.zone.today`. (The `open_task` fixture keeps its
   fixed date for the fast lane; the browser lane ignores it.)
2. Type `* pack for the trip tomorrow 2pm +camping` in the bar,
   submit → a row appears with `*`, `•`, text "pack for the trip",
   mono meta showing `14:00` and `+camping`; the input is empty and
   focused; open count incremented.
3. Toggle the kind to `○`, capture `standup 9am` → event row with `○`
   and `09:00`; events show no lifecycle buttons.
4. Complete the task → glyph `x`, row muted, open count decremented;
   reopen → back to `•`.
5. Strike it → text line-through, bullet still `•`.
6. Capture a task, `schedule` it with a date → predecessor glyph `<`;
   capture another, `migrate` it → glyph `>`.
7. Navigate: previous day shows its (empty) log and the "today" link;
   the rapid-log bar still captures into the *viewed* day? — **No.
   Ruling: capture always logs into today**, whatever day is viewed
   (rapid logging is capture, not time travel); the bar is hidden
   when viewing a day other than today.
8. Theme: cycle the toggle to dark → `html[data-theme="dark"]`,
   background changes; reload → still dark; cycle to system →
   attribute gone.
9. An invalid `/daily/not-a-date` renders today, 200.

Fast-lane controller tests cover: capture no-op on blank line,
LifecycleError → redirect + flash (post `complete` twice), auth
required on every route, theme cookie set/cleared.

## Non-goals (report, don't add)

`migrate` button here is the primitive, not the ritual); editing
entry text; deleting entries from the UI; the carried-from section in
the mock; tag filtering/search; PWA manifest/service worker; font
vendoring; per-user timezone; pagination; keyboard shortcuts.

## Review

The reviewing session checks: every ruled flow live in a browser;
the theme CSS against the token rules (no color defined only inside a
media/data-theme block; both themes legible; cookie round-trip);
capture-logs-into-today ruling; LifecycleError handling; hit-target
sizes; tab-bar placeholders disabled rather than dead; the bars; and
that `main`'s model/lib layers are untouched.
