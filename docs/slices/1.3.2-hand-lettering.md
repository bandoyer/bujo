# Slice 1.3.2 — hand lettering

A mini slice. The journal gets a hand-lettered voice: **Permanent
Marker becomes the default face for everything** — titles, entry
text, meta, day numbers — with a header cycler to switch hands,
mirroring the theme toggle. The operator picked the faces on the
[Hand-Lettered Titles canvas](https://claude.ai/code/artifact/31d0cb57-850b-4498-95b1-9dab725ccc03):
Permanent Marker (default), Rock Salt, Architects Daughter, Patrick
Hand, Gochi Hand, plus the 1.3 serif look as the sixth option.

**This spec pre-decides the judgment calls; report gaps instead of
inventing rulings.** The mechanics deliberately mirror the theme
system: a cookie, a server-stamped `data-` attribute, token
overrides. No new patterns.

## The lettering values

| Value | Face (display + body + meta) | Cookie |
|---|---|---|
| *(absent)* | Permanent Marker — the default | no cookie |
| `rock-salt` | Rock Salt | stored |
| `architects-daughter` | Architects Daughter | stored |
| `patrick-hand` | Patrick Hand | stored |
| `gochi-hand` | Gochi Hand | stored |
| `serif` | Newsreader + Public Sans + JetBrains Mono (the 1.3 look) | stored |

## Rulings

- **Full treatment.** Each handwriting face applies to display, body,
  and meta text alike via the three font tokens. Every stack keeps
  real fallbacks, and `--font-mono`'s stack keeps JetBrains Mono
  right behind the face so glyphs a handwriting font lacks (`○`, `–`)
  render from the fallback instead of as tofu.
- **Default is the absence of a cookie**, exactly like `system` in
  Theming: choosing "marker" clears the cookie; the five stored
  values live in an allowlist; anything else clears. The layout stamps
  `data-hand="<value>"` on `<html>` only for stored values — bare
  `:root` tokens ARE the marker faces, and each `[data-hand]` block
  redefines the three tokens. (Newsreader/Public Sans move from the
  bare tokens into the `serif` block; the dot-grid/theme colors are
  untouched — lettering and theme are orthogonal axes.)
- **The control is a cycler** in the header utilities, beside the
  theme toggle, same anatomy: a Stimulus-submitted form posting to
  `resource :lettering, only: :update`, cookie `permanent` +
  `same_site: :lax`, redirect back. Labels are mono and short:
  `Hand: marker` → `Hand: rock salt` → `Hand: architects` →
  `Hand: patrick` → `Hand: gochi` → `Hand: serif` → back to marker.
  All six labels are distinct strings (Capybara selects exactly).
- **Generalizing is welcome, duplicating is not.** Theming and
  lettering are the same shape; extracting a shared
  preference-cookie concern (and/or one Stimulus cycler controller
  serving both toggles) is in scope and preferred over a copy —
  jscpd stays clean. Theme behavior must not change: its cookie
  name, values, and tests stay as they are.
- **Fonts stay on Google Fonts** for now: the five new families join
  the existing `<link>` (one request; font binaries download only
  when a face is applied). The `TODO(1.7)` vendoring note now covers
  six families — update its wording, don't resolve it.
- **Hit targets ≥ 44px**, both themes legible in every hand — the
  faces recolor via the existing color tokens automatically.

## Tests

System lane (browser rules from 1.3 bind):

1. A fresh visit renders with no `data-hand` attribute (marker
   default) and the cycler reads `Hand: marker`.
2. Cycling sets `data-hand` through each stored value in order,
   reload persists, and completing the cycle returns to no attribute.
3. `Hand: serif` restores the 1.3 look's tokens (assert the computed
   font-family of the title changes between marker and serif, the
   flow-8 pattern).
4. Theme and hand compose: dark + a hand both stamp their attributes.

Fast lane: cookie set for each allowlisted value; `serif` stores and
marker clears; a crafted value clears rather than stores or 500s;
auth required on the route; theme tests untouched and green.

## Quality bars

The standard battery; parser mutation stays 1105/1105. Operator
review checks the token discipline (no face defined only inside a
`data-hand` block except as that hand's override), the fallback
stacks, and both toggles composing in a real browser.

## Non-goals (report, don't add)

A settings page; per-screen faces; font-size preferences; vendoring
fonts (1.7); persisting the preference server-side (it is a device
preference, like theme); reordering or renaming the theme toggle.
